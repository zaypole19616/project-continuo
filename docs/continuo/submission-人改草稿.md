# Continuo：让 Agent 把工作持续接住

Continuo 是一个住在本地文件夹里的 Agent，基于 Kimi Code 实现。它第一次打开文件夹时先理解再动手；把有用的上下文有选择地积累成一份可纠正的账本；需要决定时停下来问；任务结束时核验产物是否真的存在；关掉再开，从上次的位置继续。

## 1. 对未来 Agent 产品交互、Harness 与模型发展趋势的判断

### 1.1 对产品交互的三个思考

我把人与 Agent 的协作体验分成两层。一层是**显性交互**：显性交互是产品形态，是用户看到的界面，如以对话框为主的桌面端 Agent codex、manus，以 IM 交互为主的 grok bot 等等。移动互联网发展至今，不同的需求场景，早已有了最适配的产品交互的形态。（这里可以以二面中我对这个问题的回答作为补充）我认为对于产品形态而言，应该去适配。可能不存在唯一正确的交互，我认为应该是根据用户的需求场景，让 Agent 出现在用户最熟悉的产品形态下。

另一层是**隐性交互**：是 Agent 在执行与交付中让人感受到的做事方式，比如怎么了解资料、组织工作、保存成果。（这里可以以一面中我对这个问题的回答作为补充）
两层合在一起，才是完整的协作体验。
围绕这两层，我有三个 bet。

### Orderliness · 有条理和章法

我希望 Agent 能把工作打理得有条理：资料、任务与成果各有归处，用户的做事及习惯方式能留下来，下次继续时不用从头交代。重点是选择性积累有效上下文：**留下有来源、有适用范围、能修正、会失效的理解。** （这里其实我反而想表达的是，像 Agent.md 里对于那些任务的 metadata 的保留。所以我觉得，能修正还是会失效其实不是核心，重点是有来源、有适用范围。且本身他留下的不是一个偏好，而是一些客观信息。）

### Proactiveness · 主动但有分寸

主动型 Agent 最常见的失败，是把"让用户注意到我"当成目标：悬浮窗、鼠标旁的弹窗、不断的提醒。它本该减少负担，却在抢注意力。我认为好的主动是润物细无声的：在已经明确委托的范围里把事情处理好，不需要人盯着；需要人作决定时，带着必要的信息来找我；我想查看进展、修改要求、接管或暂停，随时都能做到。

### Clarity · 坦诚与清晰

AI 发展迅速，导致新的概念或功能对用户可能存在较高的理解成本。以往的产品经验往往会觉得一款产品应该是足够直观的，没有任何教程或引导，凭直觉就能直接上手使用，但现在这样做反而可能提高用户的使用门槛。所以需要帮助用户理解什么对他们最相关，即便会增加理解成本或摩擦力，也不要回避。



### 1.2 对 Harness 与模型发展趋势的判断

今天大家都在谈 Agent 的下一阶段能力：long horizon、递归自我改进。实际体验里，让模型执行，把一件具体的事做好，它已经很强；但判断哪个方向更有价值、哪里值得继续投入，是它的弱项。 模型在各类任务里常常分不清什么方向更有价值。我认为这是 long horizon、自我改进、乃至泛化到真实任务的共同卡点。

我认为这是在当下比较难解决的问题。这需要模型、harness，乃至于产品交互层面，整体一起在这三个方面同时尝试解决，构建 模型-Harness-产品 反馈的闭环。

（下面的 bet 你帮我整理一下语言 ）
1、那首先通过 Harness 去记录 human 的判断与反馈。（这里其实我觉得是下面第一点和第二点的综合。但是第一点，我觉得大部分都可以不用写。**把方向判断从模型里拿出来，做成 Harness 里的显式对象。** ）
2、整合第二、第三点吧。我觉得可以把一些判断做成比较，然后让这个 harness 把用户真实世界的反馈接回来。
3、第三点，就是要形成闭环，方向是让模型去学习这些轨迹，然后去做提升。
所以为了形成这样子的一种数据闭环。我想到的一个方向是：当用户布置了一个相对模糊、需要去判断的任务时，我们可以默认给到用户 3 个接下来可能发展的轨迹，让用户选择其中一个。

这相当于一个树状的概念，在决策口有 3 个分支，用户可以选择其中一个一直走下去。同时，系统可以建立一种能力：所有的分支都可以被保留下来，用户可以在任意一个点返回到之前的分支，并选择不同的分支往下走。对，这个其实也有点像。我觉得要做的时候，也可以参考 GitHub 的这种设计，比如 GitHub 的 work tree。



一句话概括：**今天的模型是好的执行者，差的投资人。** 围绕这一点，我的 bet 有四条。

第一，**把方向判断从模型里拿出来，做成 Harness 里的显式对象。** Agent 遇到分叉时不自己押注，而是产出选项、各自的收益、代价和可逆性，人来决定。这不是退让，是分工：模型擅长把一个选项执行到底，人擅长在选项之间下注。

第二，**Harness 的核心工作是把世界的反馈接回来，让"值钱"变成可观测的量。** 交付物是否真的存在、用户接受还是放弃、产物之后有没有被用到、哪些判断被人纠正过。这些信号今天散落在产品里没人收。收起来，长任务才有可以对齐的中间奖励，自我改进才有方向感。

第三，**把"判断"变成"比较"。** 模型做绝对判断差，做成对比较明显更稳，评测里 pairwise 比打分靠谱就是这个现象。分叉时不要求它先想对，而是让几个方向各推进一小段、各出一页摘要，在摘要之间比较。方向判断弱的时候，用小预算和可逆性兜住损失。

第四，**方向判断能力的提升，会来自带人类决策标签的真实任务轨迹，而不是更长的上下文或更多的自我博弈。** 人在第一条里做的每一次选择，加上第二条收回来的结果，是训练价值判断的真实来源。所以这个阶段的产品同时是数据采集器，产品与模型一起设计的意义就在这里。

模型侧还有一个具体约束影响 Harness 设计：长上下文和缓存命中正在变便宜，"为省 token 尽早摘要"的压力在下降，压缩的目的从省钱变成保住任务状态和注意力质量；同时前缀缓存只对完全相同的前缀整体有效，"稳定前缀、变化只追加"的纪律比以前更要紧。
