Give `understanding` (one short sentence the user takes in at a glance: what the folder is for) with the `sourceRefs` it is based on, and up to eight `points` that later tasks need — where inputs and results live, a naming or filing convention, a decision already made, what is archive rather than current. Every point needs the files it came from; if you cannot name a file for it, leave it out rather than guessing.

`suggestions` are your recommendation of what to do next, so the user does not have to work it out. When what you read shows concrete work worth doing now — a gap the guides mention, an inconsistency between files, an unfinished piece of work — add it (at most three, most valuable first) as a task you recommend, with the evidence in `reason` and the request that would start it in `prompt`. When nothing stands out, leave `suggestions` out; never invent work to have something to suggest. A choice of audience, tone or format that only matters for future writing is a point to record, not a suggestion.

Keep each point to one sentence and leave the detail in the cited files. Never record secrets or credentials. Calling this again replaces what was recorded before.
