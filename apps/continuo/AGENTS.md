# apps/continuo

Continuo's front-end: a Vite + React workbench served against the local kap-server (`kimi web`). It owns presentation only; every fact about a project comes from the `continuo` REST routes and the session WebSocket.

## Map

- `src/lib/api.ts`: typed client for `/api/v1` (workspaces, sessions, questions, approvals, `continuo*` routes, project file listing). Token comes from `#token=` or `localStorage`.
- `src/lib/ws.ts`: session event stream with reconnect; `src/lib/timeline.ts`: pure reducer from events to the conversation timeline.
- `src/pages/Launcher.tsx`: what opens first — 创建项目 and 打开已有项目 side by side (same button style) and recent projects as name + path only. The sun/moon theme button (`src/components/ThemeToggle.tsx`) sits at its top right, the same one the project view uses. 创建项目 opens `src/components/CreateProjectDialog.tsx` (项目名称 + 选择项目路径, 取消 / 保存); the path field and 打开 both open macOS's own folder chooser through `POST /api/v1/continuo/choose-folder` (the local server runs `choose folder`). `src/components/FolderPicker.tsx`, the in-page folder browser, is only the fallback when that chooser cannot open. There is no auto-restore of the last project. 使用引导 under the title replays `src/components/Onboarding.tsx`, the five-step guide shown on first launch: what Continuo is, one step per bet (Orderliness, Proactiveness, Clarity) and one for plans and lines, each naming where in the interface it shows up.
- `src/pages/Workspace.tsx`: the project view and all data flow (open, poll, send, reply, pause, resume, and the line actions: choose a plan, more plans, abandon, switch line, continue after a task). A project shows one line of work at a time: the page streams the session of the current trajectory, and switching lines swaps that session. Lines share the project folder; only a git project gives each branched line its own worktree, and then the file view, approvals and tool steps are relative to that directory and the file view returns to its root on a switch. It renders a top bar (back to projects, name, the current line's name on a branched line, path, the sun/moon theme button), `src/components/Finder.tsx` (the file browser, no tree) on the left, a draggable divider, and `src/components/Drawer.tsx` on the right.
- `src/components/Drawer.tsx`: the conversation hanging off the files. Its header holds one iOS-style segmented control (对话 / 事项 / 轨迹) at the top right. Closing cards and decision cards (`DecisionCard.tsx`) are interleaved into the conversation by time; 事项 lists the unfinished tasks of the current line in three groups (正在做 / 等你 / 停下来, `todoGroup` in `lib/trajectory.ts`); 轨迹 is `TrajectoryTree.tsx`, whose root node is the first read of the folder; it has two views, 概览 (one line per node, a node expands on click) and 详情 (every node expanded). Under the three groups, `Backlog.tsx` lists 待办 (items you add and the agent's suggestions, optionally scheduled once, daily or weekly) with its add form; a suggestion is a backlog item in the `suggested` state, shown with `SuggestionActions` (start now / cross out / keep for later). `PermissionPicker.tsx` in the composer offers Kimi Code's three permission modes with the official web UI's names and descriptions. `PlanDeck.tsx` is the one plan view, shared by the decision card and the decision node in the tree's detail view: a horizontal deck, one card per plan with the situation it suits (适合), the next card peeking; `decision.stance` holds where the agent stands — always what the choice depends on (取决于, shown above the deck) and, only when a fact in the materials settles it, one recommended plan (建议, shown first with its reason) — and a plan with a concrete problem carries 不建议 with the reason; each card has a single arrow (adopt the plan, or switch to the line that already follows it); while the decision is open the last card offers 生成更多方案 and 自定义方向 (which focuses the composer); cards still being written in parallel show as writing and keep adopting disabled, and the merged or unfinished ones are noted on the last card; `AbandonDialog.tsx` asks for an optional reason. `FileBrowser.tsx`, `Timeline.tsx`, `InteractionCards.tsx` are children of the two panes. `InitCard.tsx` stays at the top of the conversation: while the folder is read it shows the current step and the files read so far; when done and nothing has started yet it shows a one-sentence summary and, when the model has any, 建议的下一步事项 via `SuggestedTodos.tsx` — the backlog items suggested by that task, each with start now / cross out / keep for later (`{todo_id}:start`, `:dismiss`, `:accept`) and its outcome once handled; every finished task's next step shows the same way under its closing card; an empty folder gets no suggestions; after the first task it folds into a one-line summary; a failed read shows the error card with 重新了解 (`init:retry`, since opening only reads the first time). A failed task shows `ErrorCard.tsx` right after it, following Kimi Code's own error card: the title comes from the error code (`lib/errors.ts`, same wording as the official web UI), the provider message stays verbatim, code / HTTP status / request and trace ids sit under 详情, and a spent plan names the limit and when it resets from `/oauth/usage`.
- `src/lib/trajectory.ts`: pure helpers over the project doc — the current line, a plan's state on a line (current / open / elsewhere / abandoned), and `buildTrunk`, which lays out the tree: the current line as the trunk, each decision right before the work it led to, plan branches hanging off their decision, lines continued after a task hanging off that task. Covered by `trajectory.test.ts`.
- The app mark is `src/assets/continuo-mark.png`, a transparent mask of the dotted branch; the launcher tints it with `--mark-paper` / `--mark-ink` per theme, and `public/favicon.svg` embeds the same mask and follows the system color scheme. Never ship the mark with a baked-in background.
- `src/lib/theme.ts`: the theme preference (`continuo.theme`: system by default, or dark / light) applied as `html[data-theme]`.
- The look comes from the official Kimi Code web UI that ships in this repo as a prebuilt bundle (`apps/kimi-code/dist-web`): `src/theme.css` starts from its design tokens (colors, radii, composer and send-button values), read out of `dist-web/assets/index-*.css`. Dark is `:root`, light is `[data-theme='light']` — the same variables with other values. Files and conversation share one surface with no divider between them. `src/components/Onboarding.tsx` runs a four-step modal on first launch (`continuo.onboarded`); it is the only place the three interaction bets are named.
- `src/components/ui/`: the shadcn/ui layer (Radix primitives + `cn`). Interactive widgets — menus, dialogs, tabs, buttons, inputs — come from here, so portalling, focus, keyboard and aria are the library's job, not ours.
- `src/theme.css`: the only place for colors, radii, type sizes and shadows. It defines Kimi Code's own tokens, then maps shadcn's names (`--primary`, `--muted`, `--border`, …) onto them and exposes both through `@theme inline`. Components use tokens, never literal colors. Keep unlayered element rules out of it: an unlayered `button { color: … }` beats every Tailwind utility.

## Rules

- Reducers and API helpers stay pure; components never parse wire events themselves.
- A lost connection shows one reconnecting notice that clears itself; raw browser or provider error text never reaches the screen (`friendlyError` in `lib/timeline.ts`).
- Chinese UI copy, English identifiers. No user-visible text under 12px.
- Never narrate the interface. What the product does shows up as conversation, files and work logs, not as hints explaining itself.
- Keep the project view responsive down to 860px (the drawer drops below the files, the divider hides); headers never wrap. One control per state: the drawer's segmented control is the only mode switcher, and the tree is the only place lines are listed.
- Text sent into the conversation on the user's behalf (choosing a plan, asking for more, continuing) is plain language; tool names never appear in it.
- A disabled action says why: wrap it in `Hint` so the reason shows on hover.
- Do not add a second Markdown renderer or icon set; `lib/markdown.ts` and `lucide-react` are the ones in use.
- Run `pnpm -C apps/continuo dev` with `KIMI_PORT` pointing at a `kimi web` started with `KIMI_CODE_EXPERIMENTAL_CONTINUO=1`.
