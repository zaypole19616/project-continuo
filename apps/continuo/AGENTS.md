# apps/continuo

Continuo's front-end: a Vite + React workbench served against the local kap-server (`kimi web`). It owns presentation only; every fact about a project comes from the `continuo` REST routes and the session WebSocket.

## Map

- `src/lib/api.ts`: typed client for `/api/v1` (workspaces, sessions, questions, approvals, `continuo*` routes, project file listing). Token comes from `#token=` or `localStorage`.
- `src/lib/ws.ts`: session event stream with reconnect; `src/lib/timeline.ts`: pure reducer from events to the conversation timeline.
- `src/pages/Launcher.tsx`: what opens first — 新建项目 and 打开已有项目 side by side (same button style) and recent projects as name + path only. `src/components/FolderPicker.tsx` is the one dialog to browse, create or open a folder. There is no auto-restore of the last project.
- `src/pages/Workspace.tsx`: the project view and all data flow (open, poll, send, reply, pause, resume, and the line actions: choose a plan, more plans, abandon, switch line, continue after a task). A project shows one line of work at a time: the page streams the session of the current trajectory, and switching lines swaps that session and the files shown (a branched line has its own copy of the folder; paths in the file view, approvals and tool steps are relative to it, and the file view returns to that copy's root on a switch). It renders a top bar (back to projects, name, the current line's name on a branched line, path, the sun/moon theme button), `src/components/Finder.tsx` (the file browser, no tree) on the left, a draggable divider, and `src/components/Drawer.tsx` on the right.
- `src/components/Drawer.tsx`: the conversation hanging off the files. Its header holds one iOS-style segmented control (对话 / 事项 / 轨迹) at the top right. Closing cards and decision cards (`DecisionCard.tsx`) are interleaved into the conversation by time; 事项 lists the unfinished tasks of the current line in three groups (正在做 / 等你 / 停下来, `todoGroup` in `lib/trajectory.ts`); 轨迹 is `TrajectoryTree.tsx`, whose root node is the first read of the folder. `PlanList.tsx` is the one plan list, shared by the decision card and the zoomed-in decision node; while plans are still being written in parallel it lists the authors still writing and keeps choosing disabled, and afterwards notes the ones merged or unfinished; `AbandonDialog.tsx` asks for an optional reason. `FileBrowser.tsx`, `Timeline.tsx`, `InteractionCards.tsx` are children of the two panes. `InitCard.tsx` stays at the top of the conversation: progress while the folder is being read, then what was understood (with its work log), or the failure with 重新了解. A failed task shows `ErrorCard.tsx` right after it, following Kimi Code's own error card: the title comes from the error code (`lib/errors.ts`, same wording as the official web UI), the provider message stays verbatim, code / HTTP status / request and trace ids sit under 详情, and a spent plan names the limit and when it resets from `/oauth/usage`.
- `src/lib/trajectory.ts`: pure helpers over the project doc — the current line, a plan's state on a line (current / open / elsewhere / abandoned), and `buildTrunk`, which lays out the tree: the current line as the trunk, each decision right before the work it led to, plan branches hanging off their decision, lines continued after a task hanging off that task. Covered by `trajectory.test.ts`.
- The app mark is `src/assets/continuo-mark.png`, a transparent mask of the dotted branch; the launcher tints it with `--mark-paper` / `--mark-ink` per theme, and `public/favicon.svg` embeds the same mask and follows the system color scheme. Never ship the mark with a baked-in background.
- `src/lib/theme.ts`: the theme preference (`continuo.theme`: system by default, or dark / light) applied as `html[data-theme]`.
- The look comes from the official Kimi Code web UI that ships in this repo as a prebuilt bundle (`apps/kimi-code/dist-web`): `src/theme.css` starts from its design tokens (colors, radii, composer and send-button values), read out of `dist-web/assets/index-*.css`. Dark is `:root`, light is `[data-theme='light']` — the same variables with other values. Files and conversation share one surface with no divider between them. `src/components/Onboarding.tsx` runs a four-step modal on first launch (`continuo.onboarded`); it is the only place the three interaction bets are named.
- `src/components/ui/`: the shadcn/ui layer (Radix primitives + `cn`). Interactive widgets — menus, dialogs, tabs, buttons, inputs — come from here, so portalling, focus, keyboard and aria are the library's job, not ours.
- `src/theme.css`: the only place for colors, radii, type sizes and shadows. It defines Kimi Code's own tokens, then maps shadcn's names (`--primary`, `--muted`, `--border`, …) onto them and exposes both through `@theme inline`. Components use tokens, never literal colors. Keep unlayered element rules out of it: an unlayered `button { color: … }` beats every Tailwind utility.

## Rules

- Reducers and API helpers stay pure; components never parse wire events themselves.
- A lost connection shows one reconnecting notice that clears itself; raw browser or provider error text never reaches the screen (`friendlyError` in `lib/timeline.ts`).
- Chinese UI copy, English identifiers. No user-visible text under 12px.
- Never narrate the interface. What the product does shows up as conversation, files and work logs, not as hints explaining itself.
- Keep the project view responsive down to 860px (the drawer drops below the files, the divider hides); headers never wrap. One control per state: the drawer's segmented control is the only mode switcher, and the tree is the only place lines are listed.
- Text sent into the conversation on the user's behalf (choosing a plan, asking for more, continuing) is plain language; tool names never appear in it.
- A disabled action says why: wrap it in `Hint` so the reason shows on hover.
- Do not add a second Markdown renderer or icon set; `lib/markdown.ts` and `lucide-react` are the ones in use.
- Run `pnpm -C apps/continuo dev` with `KIMI_PORT` pointing at a `kimi web` started with `KIMI_CODE_EXPERIMENTAL_CONTINUO=1`.
